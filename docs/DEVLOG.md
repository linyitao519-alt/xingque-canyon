# 星阙峡谷 · 第一版可玩原型

手机横屏浏览器里的本地单人三路 MOBA（3v3）。玩家操控蓝方星璃，蓝方两名队友和红方三名对手由 AI 控制。
TypeScript + Canvas 2D，零运行时依赖。

## 启动

```bash
npm start            # 等价于 node server.mjs，默认端口 5173（已带编译好的 dist/，无需安装依赖）
```

改了 `src/` 之后：

```bash
npm install          # 只装 TypeScript
npm run build        # 或 npm run dev（编译后启动）
```

需要 Node 18+。不能直接双击 `index.html`（浏览器不允许 file:// 加载模块和 JSON）。

## 用手机打开

1. 手机和电脑连同一个 Wi-Fi。
2. `npm start` 会打印一行「手机: http://192.168.x.x:5173/」，在手机浏览器里输入这个地址。
3. 把手机横过来（竖屏会提示并暂停）。右上角按钮可进全屏（安卓 Chrome）；iPhone Safari 没有全屏 API，
   用「分享 → 添加到主屏幕」从桌面图标打开即可去掉地址栏。
4. 打不开时检查电脑防火墙是否放行 5173 端口。

## 操作

| 操作 | 触屏 | 桌面调试 |
| --- | --- | --- |
| 移动 | 左半屏任意位置按下出现摇杆 | WASD / 方向键 |
| 普攻 | 右下剑形按钮（可按住连续攻击） | J / 空格 |
| 弦月 / 定星 / 三星结界 | 按住技能键拖动瞄准，松手施放；拖到右上「取消」放弃；轻点 = 自动朝最近敌人 | 1 / 2 / 3（自动瞄准）或鼠标拖技能键 |
| 重新开始 | 结算界面「再来一局」 | R |

摇杆、普攻、技能各自跟踪自己的手指，可以一边移动一边拖动瞄准。

调试参数：`?auto=1` 让 AI 代打星璃；`?speed=8` 加速模拟。控制台里 `__xq.game` 是对局对象。

## 镜头设置

正式默认：**屏高 102、敌塔屏边提示开、技能瞄准取景开、塔偏移关**，界面上不显示试验按钮。两档屏高共用同一套模拟，射程、移速、碰撞、技能判定完全相同。

| 项 | 默认 | 调试参数 | 作用 |
| --- | --- | --- | --- |
| 屏高 | 102 | `?viewh=120` | 只改镜头缩放和贴图倍率 |
| 敌塔屏边提示 | 开 | `?hint=0` | 敌塔底座出了取景框且玩家在其射程内 → 框边出现指向塔的箭头；已锁定玩家时变红、放大、闪动并带「!」。箭头区上沿留在计时条下方 |
| 技能瞄准取景 | 开 | `?aimcam=0` | 拖动超过死区后镜头朝 `aimWorld()` 的落点平移（平滑时间 0.16s），上限是玩家自己仍留在取景框内；松手或取消后回中 |
| 塔偏移 | 关 | `?toweroffset=1` | 仅屏高 102。敌塔锁定玩家且底座出框时，用最小位移把底座拉回框内，上限横 19 / 纵 26；脱锁后保持 0.7 秒再回中 |
| 试验按钮 | 隐藏 | `?lab=1` | 在计时条下显示四个开关 |

取景框 = 安全区内再让开顶部计时条（`Hud.safeRect()`）。代码在 `src/camrig.ts`。
验证：`python3 tests/e2e_camera.py`。`docs/camera-compare-120-vs-102.mp4` 是三档对比，`docs/real-combat-viewh102.mp4` 是默认设置下的实战复测。

## 动画、特效、音效（v8）

素材来自 `xingque-v7-update`，由 `tools/import_anim.py` 导入。

- **序列帧**（`assets/anim/`，清单 `anim.json`）：六名英雄和四种小兵各有待机 4 帧、跑步 6 帧、攻击 4 帧，统一朝右下，朝左时水平翻转。
  状态只由玩法决定：出手后把攻击帧完整播一遍，否则移动播跑步、静止播待机。英雄的出手帧（第 3 帧）对在普攻 0.18 秒前摇结束的时刻；
  小兵的伤害是瞬时结算的，所以从出手帧直接播起。放技能也播出手动作。帧率在 `anim.json` 里改。
  导入时英雄帧缩到 ½、小兵缩到 ¼（解码后内存约 30MB，原尺寸约 220MB）。后台加载，加载完自动替换静态图；`?anim=0` 关闭。
- **走动平滑**：原稿的跑步帧在格子里左右漂移 41–118px（约为身体宽度的 10%–40%），循环起来像抽搐。现在做了三件事：
  ① 导入时稳帧，把待机和跑步各帧按上半身重心对齐到同一条竖线（漂移降到 1px 以内）；
  ② 跑步帧按实际走过的距离推进（英雄每 33 世界单位一圈、小兵 17），停下不会原地踏步；
  ③ 每帧最后 45% 的时间把下一帧淡入。另外朝向换边加了回差，跑/停状态保持 0.15 秒，避免来回闪。`?animsmooth=0` 可关掉②③和回差做对比。
- **特效**（`assets/fx/`）：弦月飞行体、定星星标与四帧爆开、三星结界的边线和顶点、星璃普攻弹体、蓝红塔弹。缺图时退回代码绘制。
- **音效**（`assets/audio/`，代码在 `src/audio.ts`）：由模拟层已有事件触发——英雄出手、命中、星标落地、结界闭合、塔受击、塔毁、胜利、失败；弦月出手复用出手音效并降调。
  离星璃越远音量越小，300 单位外不响；命中和塔受击做了限频。首次触控后才解锁（浏览器限制）。右上角有静音键，`?mute=1` 默认静音。
- 验证：`npm test`（含 `tests/anim.test.mjs`）和 `python3 tests/e2e_media.py`。

## 和素材包不一致、需要你确认的地方

- **塔序**：`map-layout.svg` 图例写「1 为外塔」，但 `map.json` 里蓝方上路、红方下路的 t1 是最靠近己方水晶的那座。
  原型按塔在兵线上的实际位置排序（离己方水晶最远的先解锁），id 保持 JSON 原样。如果你本意是按 id 解锁，
  改 `sim.ts` 里 `reset()` 的排序即可，但那两路会变成必须先穿过两座无敌塔。
- **建筑锚点**：素材包 README 说所有单件按底边中心 (384, 512) 对齐世界坐标。英雄、小兵、地形我照做了；
  塔和水晶改用**底座占地的中心**对齐，因为碰撞圆、小兵围攻的位置都以世界坐标为圆心，按底边对齐会让塔身整体偏北约 10 个单位。
  要改回去，把 `tools/import_runtime.py` 里建筑的 `anchor_y` 换成 512 重新导入。
- **底图里的立体物加了碰撞**：10 个碰撞圆（4 根桥柱 + 6 块岩石）是 `map.json` 之外新增的阻挡，位置取自底图。
- **三星结界消耗星标**：按「施放成功即消耗两枚」实现（没命中任何单位也消耗）。

## v12：three.js 渲染 + 单文件版
- 渲染后端默认 three.js r128（`lib/three.min.js`，取自 github.com/mrdoob/three.js，MIT）。沿用全部 2D 素材，玩法、镜头、数值不变。`src/three_layer.ts`。

  - 立体层逐件是 three.js 的贴图片：单位直接取帧带（UV 取帧、翻转、下一帧淡入、星盘挂件）；岩石、树、塔、基地先各自烘成一张小纹理再复用。遮挡顺序 = 按触地点 Y 排序后的提交顺序。
  - 弹体、血条、名字、伤害数字和 HUD 画在最上层的 2D 画布。
  - 烘成纹理的地物不再随时间摆动（芦苇、灌木）；塔和基地的"未解锁/被毁"状态各有一张。
